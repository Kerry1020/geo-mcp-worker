第一类：地理编码（Geocoding）— 地址↔坐标
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Nominatim (OpenStreetMap)
   - 网址: https://nominatim.openstreetmap.org
   - 场景: 正/逆向地理编码，地址→坐标，坐标→地址
   - 鉴权: 无需 key，需 User-Agent
   - 限制: 1 req/s（硬限制）
   - 中国覆盖: ✅ 中文地址解析精准（实测"陆家嘴"、"云锦路"均命中）
   - CF Workers: ✅ HTTPS fetch 直接调用
   - 接入难度: ★☆☆☆☆（已在用）
   - 评估: 当前主力，无替代必要

2. Pelias (开源地理编码器)
   - 网址: https://pelias.io
   - 场景: 自部署地理编码，支持自动补全、结构化搜索
   - 鉴权: 自部署无需 key；公共实例 Geocode Earth 需付费
   - 限制: 自部署无限制，但需要服务器 + 全球 OSM 数据导入（~100GB）
   - 中国覆盖: ✅ 使用 OSM 数据，同 Nominatim
   - CF Workers: ❌ 无法自部署在 Workers 上；公共实例 geocode.earth 收费
   - 接入难度: ★★★★★（需独立服务器 + 数据导入）
   - 评估: 过重，不适合当前架构

3. OpenCage
   - 网址: https://opencagedata.com/api
   - 场景: 正/逆向地理编码，聚合多数据源
   - 鉴权: 需要 API key（免费 2500 次/天）
   - 限制: 免费层 2500 req/day
   - 中国覆盖: ✅ 覆盖全球
   - CF Workers: ✅ REST API
   - 接入难度: ★★☆☆☆
   - 评估: 免费额度比 Nominatim 更低（2500/天 vs 无限但 1/s），无优势

4. Geocode Earth (Pelias 公共实例)
   - 网址: https://geocode.earth
   - 场景: 托管版 Pelias，支持自动补全
   - 鉴权: 需要 API key，有免费试用
   - 限制: 付费
   - 中国覆盖: ✅
   - CF Workers: ✅ REST API
   - 接入难度: ★★☆☆☆
   - 评估: 付费服务，违反零成本原则

第二类：POI / 空间查询
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

5. Overpass API (OpenStreetMap)
   - 网址: https://overpass-api.de/api/interpreter
   - 场景: 空间 POI 查询（餐厅、学校、医院、地铁站等 20+ 类型）
   - 鉴权: 无需 key
   - 限制: 10s 超时，结果集大小限制
   - 中国覆盖: ✅ 餐厅/学校/地铁/医院均有
   - CF Workers: ✅ HTTPS POST
   - 接入难度: ★☆☆☆☆（已在用）
   - 评估: 当前主力 POI 引擎

6. Overpass Ultra
   - 网址: https://overpass-ultra.trailsta.sh
   - 场景: Overpass 的 Web 前端增强版，非独立 API
   - 评估: 非可编程 API，仅用于人工调试 Overpass 查询语句，不可接入

7. Wikidata SPARQL
   - 网址: https://query.wikidata.org
   - 场景: 通过 SPARQL 查询结构化数据（地铁站点坐标、线路信息等）
   - 鉴权: 无需 key
   - 限制: 查询复杂度限制，非实时
   - 中国覆盖: ✅ 有中国城市地铁/地标的结构化数据
   - CF Workers: ✅ REST API（SPARQL over HTTP）
   - 接入难度: ★★★☆☆（需要写 SPARQL 查询）
   - 评估: 可作为补充数据源，用于获取地铁线路拓扑结构、站点元数据

第三类：路径规划（Routing）— 点到点距离/时间
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

8. OSRM (Open Source Routing Machine)
   - 网址: https://router.project-osrm.org
   - 场景: 驾车/步行/骑行路径距离和时间
   - 鉴权: 无需 key
   - 限制: 公共服务器非 SLA 保证，步行 >2km 时间严重低估（已加 sanity filter）
   - 中国覆盖: ✅ 全球 OSM 道路网
   - CF Workers: ✅ REST API
   - 接入难度: ★☆☆☆☆（已在用）
   - 评估: 当前主力路由引擎，步行需自行校准

9. Valhalla (开源路由引擎)
   - 网址: https://github.com/valhalla/valhalla
   - 场景: 多模式路由（驾车/步行/骑行/公交），支持等时线计算
   - 鉴权: 自部署无需 key；公共实例由 Stadia Maps / Mapbox 提供（需 key）
   - 限制: 自部署需编译 C++ + 导入 OSM 数据
   - 中国覆盖: ✅ 全球 OSM
   - CF Workers: ❌ 无法自部署；公共实例需付费 key
   - 接入难度: ★★★★★（C++ 编译 + 数据导入）或 ★★☆☆☆（付费公共实例）
   - 评估: 功能比 OSRM 强（支持多模式+等时线），但自部署成本极高；
           Stadia Maps 有免费层 5000 req/月，值得后续评估

10. OpenRouteService (海德堡大学)
    - 网址: https://openrouteservice.org
    - 场景: 路由规划 + 等时线 + 地理编码 + POI
    - 鉴权: 需要免费 API key（注册即得）
    - 限制: 免费层 2000 req/天
    - 中国覆盖: ✅ 全球
    - CF Workers: ✅ REST API
    - 接入难度: ★★☆☆☆
    - 评估: 功能全面（路由+等时线+POI+编码），免费 key 注册简单；
            ⚠️ 但公交/Transit 模式需要 GTFS 数据支撑，中国无 GTFS 则不可用

11. GraphHopper
    - 网址: https://github.com/graphhopper/graphhopper
    - 场景: 路由引擎，Java 开源，支持 PT（Public Transit）模块
    - 鉴权: 自部署无需 key；公共 API 需 key（免费额度有限）
    - 限制: Java 应用，需服务器；PT 模块需 GTFS 数据
    - 中国覆盖: ✅ 全球 OSM 道路网；但 PT 模块无中国数据
    - CF Workers: ❌ Java 应用无法部署
    - 接入难度: ★★★★☆
    - 评估: PT 模块理论上支持多模态公交，但中国无 GTFS 等于无用

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
第四类：公共交通 / 多模态路由（Transit Routing）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

12. Transitous
    - 网址: https://transitous.org
    - GitHub: https://github.com/public-transport/transitous
    - 场景: 全球免费公交路由服务，社区运营，FOSS，基于 MOTIS 引擎
    - 鉴权: 完全免费，无需 key
    - 限制: 社区维护，非 SLA
    - 中国覆盖: ❌ 完全没有中国数据（feed 目录无 CN 相关文件）
    - 亚洲覆盖: ❌ 几乎没有亚洲数据（仅有部分欧洲/北美/澳洲）
    - CF Workers: ✅ REST API（但没中国数据）
    - 接入难度: ★★☆☆☆（API 简单，但无中国数据）
    - 评估: 理念完美（免费+无 key+全球），但中国覆盖为零，无法使用

13. OpenTripPlanner (OTP)
    - 网址: https://www.opentripplanner.org
    - 场景: 业界标准的多模态公交路由引擎
    - 鉴权: 开源自部署
    - 限制: Java 应用，需要 GTFS + OSM 数据，服务器内存需求大（>8GB）
    - 中国覆盖: ⚠️ 技术上支持全球，但需要自备 GTFS 数据
    - CF Workers: ❌ Java 应用，无法部署
    - 接入难度: ★★★★★
    - 评估: 业界标准但过重，且中国 GTFS 数据缺失

14. MOTIS (Multi-Objective Transit Simulation)
    - 说明: Transitous 底层使用的路由引擎
    - 场景: 高性能多目标公交路由
    - 评估: Transitous 的底层引擎，同 Transitous，中国数据为零

15. Navitia (法国 KissKissBankBank / Hove)
    - 网址: https://api.navitia.io
    - 场景: 公交路由 API，覆盖法国及部分欧洲城市
    - 鉴权: 需注册免费 key
    - 中国覆盖: ❌ 仅法国/欧洲
    - CF Workers: ✅ 但没中国数据
    - 接入难度: ★★☆☆☆
    - 评估: 欧洲强但中国零覆盖

16. Transitland Routing API
    - 网址: https://www.transit.land
    - 场景: 全球公交数据聚合 + 路由
    - 鉴权: 免费 API key
    - 中国覆盖: ❌ 无中国 feed
    - CF Workers: ✅ REST API
    - 接入难度: ★★☆☆☆
    - 评估: 全球 GTFS 聚合平台，但中国为零

第五类：商业地图 API（有免费层，但需 key）

17. 高德地图 API (Amap)
    - 网址: https://lbs.amap.com/api
    - 场景: 地理编码 + 路线规划 + 公交/地铁路线 + 静态地图
    - 鉴权: 需注册免费 API key
    - 限制: 免费 5000 次/天（个人开发者），可申请提升
    - 中国覆盖: ✅✅✅ 中国最强覆盖，公交/地铁/步行/驾车全覆盖
    - CF Workers: ✅ REST API
    - 接入难度: ★☆☆☆☆（文档完善，SDK 齐全）
    - 评估: ⭐ 中国公共交通路线规划的最佳选择
            免费额度足够个人项目；公交+地铁+步行一体化；
            但需要 API key，违反"零鉴权"原则

18. 百度地图 API
    - 网址: https://lbsyun.baidu.com
    - 场景: 同高德（编码+路线+公交+地铁）
    - 鉴权: 需注册免费 key
    - 限制: 免费额度与高德相当
    - 中国覆盖: ✅✅✅
    - CF Workers: ✅ REST API
    - 接入难度: ★☆☆☆☆
    - 评估: 与高德同等能力，可做 backup；坐标系是 BD-09 需转换

19. 腾讯地图 API
    - 场景: 同上
    - 评估: 第三选择，覆盖和功能不如高德/百度

20. HERE Maps API
    - 网址: https://developer.here.com
    - 场景: 公交路由 + 驾车 + 步行（Public Transit Routing API v8）
    - 鉴权: 需注册免费 key
    - 限制: 免费层 5000 req/月
    - 中国覆盖: ✅ 全球覆盖（含中国公交数据）
    - CF Workers: ✅ REST API
    - 接入难度: ★★☆☆☆
    - 评估: 海外公交路由最佳选择；中国也能用但不如高德精准；
            适合"全球通用"场景

21. Mapbox API
    - 网址: https://mapbox.com
    - 场景: 地图 + 路由 + 地理编码
    - 鉴权: 需免费 key
    - 限制: 50000 map loads/月
    - 中国覆盖: ✅ 全球
    - CF Workers: ✅ REST API
    - 接入难度: ★★☆☆☆
    - 评估: ⚠️ 不支持公交/Transit 路由，仅驾车/步行/骑行；
            地图渲染强但路由能力不如 HERE

22. MobilityDatabase (原 TransitFeeds)
    - 网址: https://mobilitydatabase.org
    - 场景: 全球 GTFS/GTFS-RT feed 目录
    - 鉴权: 免费 API key
    - 中国覆盖: ❌ 中国 feed 极少
    - CF Workers: ⚠️ 需下载+解析 GTFS zip 文件，CPU 超限
    - 接入难度: ★★★☆☆
    - 评估: 全球 GTFS 目录，但中国数据缺失

23. China-City-Subway (Seaony)
    - 网址: https://github.com/Seaony/china-city-subway
    - 场景: 全国已开通地铁城市的站点/线路 SQL 数据
    - 鉴权: 无
    - 中国覆盖: ✅ 全国已开通城市（但数据截至 2018-07，已过时 7 年）
    - CF Workers: ⚠️ SQL 格式，需转为 JSON
    - 接入难度: ★★★☆☆
    - 评估: 数据严重过时，2018 年后新增线路全部缺失

24. China-Metro-Info (HKUST)
    - 网址: https://github.com/HKUST-Trans-Lab/China-Metro-Info
    - 场景: 通过百度地图 API 获取全国地铁站点经纬度 JSON
    - 鉴权: 获取数据需百度 key；已生成的 JSON 可直接用
    - 中国覆盖: ✅ 有广州/深圳示例 JSON
    - CF Workers: ✅ 静态 JSON 可 fetch
    - 接入难度: ★★★☆☆（需要自己跑脚本生成其他城市数据）
    - 评估: 数据格式好（WGS-84 坐标+距离），但需自行生成；仅站点坐标，无时刻表

25. CPTOND-2025 (中国公共交通网络数据集)
    - 网址: https://jean89091515.github.io/CPTOND/
    - 论文: Nature Scientific Data 2025
    - 场景: 学术级全国公共交通网络数据（线路+站点+时刻表）
    - 鉴权: 学术免费
    - 中国覆盖: ✅ 全国
    - CF Workers: ❌ 静态数据集，非 API，需下载后处理
    - 接入难度: ★★★★☆
    - 评估: 数据质量最高（学术论文级），但获取和使用门槛高；

26. shmetro-api (cnmetro)
    - 网址: https://github.com/cnmetro/shmetro-api
    - 场景: 上海地铁专用 API
    - 鉴权: 无
    - 中国覆盖: ⚠️ 仅上海
    - CF Workers: ✅ 轻量 REST
    - 接入难度: ★☆☆☆☆
    - 评估: 仅覆盖 1 个城市，无法扩展

27. 上海市公共数据开放平台
    - 网址: https://data.sh.gov.cn
    - 场景: 上海市政府开放数据（含公交/地铁/出租等）
    - 鉴权: 需注册+审批
    - 中国覆盖: ⚠️ 仅上海
    - CF Workers: ⚠️ 非标准 API
    - 接入难度: ★★★☆☆
    - 评估: 政府数据，需要审批流程

28. AmapMetro (Gitee)
    - 网址: https://gitee.com/scuzzk/AmapMetro
    - 场景: 从高德地图爬取地铁线路数据，生成 SHP/GeoJSON
    - 鉴权: 需高德 key
    - 中国覆盖: ✅ 全国
    - CF Workers: ⚠️ 工具脚本，非 API
    - 接入难度: ★★★☆☆
    - 评估: 数据获取工具，非可接入 API

│ 结论：公共交通路线规划的中国数据死局                                        │
│                                                                         │
│ 1. 开源方案（Transitous/Navitia/OTP/GraphHopper/MOTIS）全部依赖 GTFS     │
│    数据，而中国城市不发布 GTFS feed → 中国覆盖为零                         │
│                                                                         │
│ 2. 静态数据（China-City-Subway/China-Metro-Info/CPTOND）有站点坐标       │
│    但没有实时时刻表，无法做路线规划                                        │
│                                                                         │
│ 3. 唯一能做中国公交+地铁路线规划的：高德/百度/HERE，但需要 API key        │
└─────────────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────────────┐
│ 如果要实现"全球+中国"公共交通路线规划，建议分层策略：                        │
│                                                                         │
│ Layer 0（当前）: OSRM + Nominatim + Overpass → 驾车/步行/骑行            │
│ Layer 1（低成本）: Transitous → 海外公交路由（免费无 key）                 │
│ Layer 2（需 key）: 高德 API → 中国公交/地铁路由（免费 key）               │
│ Layer 3（需 key）: HERE API → 全球公交路由兜底（免费 key）                │
│                                                                         │
│ Agent 调度逻辑：                                                         │
│   中国地址 → 高德公交 API                                                 │
│   海外地址 → Transitous                                                   │
│   都失败 → OSRM 步行/驾车 fallback                                        │
└─────────────────────────────────────────────────────────────────────────┘
